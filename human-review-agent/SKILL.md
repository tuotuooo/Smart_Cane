# Skill 2：领导审稿分身

> 人篇章（软技能线）Skill 2 · 底层操作系统见 [`human-social-engineering`](../human-social-engineering/)（Skill 0）。

## 一、定位

用 **+1 的评价视角和话术风格**，对汇报稿、PPT、邮件、微信做**发前预审**。
不是在写完之后挑毛病，是在发出之前先让“领导的判断标准”过一遍。

## 二、触发场景

- 任何发给 +1 的书面内容；
- 尤其是汇报、方案、资源申请、风险说明；
- 拿不准“这么写会不会被理解成要钱 / 计较 / 推责”时。

## 三、核心动作（七项预审清单）

1. **结论前置**：前三句有没有说清进度、成果、待决策；
2. **成果量化**：有没有数字，还是只有“完成了”；
3. **范围精炼**：是不是“多而杂”，有没有收窄到旗舰 / 重点；
4. **风险边界**：是“我们不管”，还是“支持边界 + 建议路径”；
5. **资源请求**：是要预算，还是给选项请他定；
6. **政治安全**：有没有越级、抢功、情绪化、推责；
7. **可留痕**：口头内容有没有书面纪要。

## 四、关键话术

> “明白，我收窄到旗舰，先出 5 页骨架您看方向，确认后再展开。”

（把“多而杂”的批评，换成一个可执行的收窄选项。）

## 五、红线

- 不生成虚假数据；
- 不教伪装；
- 不把预审变成讨好训练。

> 审稿分身的目标是**让事实以对方能结算的方式呈现**（Skill 0），不是把假话包装得更像真话。

## 六、与 Skill 0 的关系

预审的七项清单，本质是提前预判对方会用什么框架（Skill 0 第二步“给选项不给证明题”）。写汇报先过 Skill 3 定结构，再过本 Skill 做发前检查。
