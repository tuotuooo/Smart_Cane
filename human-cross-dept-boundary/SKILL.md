# Skill 5：跨部门协作边界管理

> 人篇章（软技能线）Skill 5 · 底层操作系统见 [`human-social-engineering`](../human-social-engineering/)（Skill 0）。

## 一、定位

让额外贡献**被看见、被归因、被合理回报**，同时不被无限消耗。
帮忙可以，但不能默认变成你的本职；边界不说，就会被当成“你顺手做的”。

## 二、触发场景

- 给别人做工具、接加急需求；
- 跨部门提要求、成果被理所当然化；
- 手上有多个项目，却不断被插需求打断。

## 三、核心动作

1. **统一需求入口**：所有新需求走同一渠道，附带对原进度的影响；
2. **给选择题**：新增需求进来，请对方或领导定优先级；
3. **让打断成本可见**：每次插需求，同步对原计划的影响；
4. **设 WIP 上限**：同时开发不超过 N 项，第三项排队或替换；
5. **交付时设边界**：小问题集中反馈，大调整看优先级；
6. **成果文档化**：周报写“可复用资产”，不写“帮忙”；
7. **让受益方替你说**：正式反馈、复盘、使用记录中留下归因。

## 四、关键话术

> “这个需求我记下了。目前手上有 A、B 在开发，新增 C 会影响 A 的交付时间。请确认 C 的优先级，以及是否接受 A 延期。”

（不直接拒绝，也不默默全接；把优先级决策交回给对方。）

## 五、红线

- 不默默加班全接；
- 不自己替领导排序还不说；
- 不用情绪对抗。

## 六、与 Skill 0 的关系

“让成本可见”“成果文档化”就是 Skill 0 的**感知管理 + 归因设计**：把隐形的付出写成显性的资产。“请确认优先级”是**框架控制**——把“你能不能帮我”换成“请做优先级决策”。若因此陷入委屈，接 Skill 8。
