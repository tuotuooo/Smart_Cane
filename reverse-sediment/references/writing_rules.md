# 写作硬规矩

> 这份文件管的是"写出来能不能被复用"。判据形态、证据强度、坑的写法、推翻记录的格式。
> 反例全部来自真实项目，不是编的。

---

## 一、结论句：三种坏形态

### 坏形态 1：只有过程

```
❌ 我们尝试了改语言包，连续四次刷机都没有变化，后来发现是链式兜底。
```

问题：读者不知道"链式兜底"是什么意思，也不知道下次怎么提前发现。

```
✅ 语言包改了没生效时，先查"上层是否已把 NULL 兜成默认值"。
   判据：如果目标分支的上游有一句 `x = x ? x : DEFAULT`，那么目标分支的
   "默认值"逻辑就是死代码，改它永远不生效。
```

### 坏形态 2：没有主语

```
❌ 这个要放在前面，不然会黑屏。
```

哪个"这个"？什么在前面？

```
✅ 开代理必须在 App 进到目标页面之后。顺序反了，App 加载时连不上网会直接黑屏，
   看起来像反抓包，实际是时序问题。
```

### 坏形态 3：把不确定写成确定

```
❌ vib_start 不振是因为 cycles 参数太小。
```

这是猜测，但写成了结论。下一轮有人照着改参数，白改一轮。

```
✅ vib_start(1,5) 实测无振动，原因未闭合。三个候选：
   ① cycles 不是次数而是 tick 数，5 太短
   ② 马达需先经 app_motor_control 使能
   ③ 0x8011 IPC 消息在目标核无 handler（分发表里查不到该 ID）
   下一步：在已确认马达正常的固件上依次试 ① 和 ②。
```

**不确定不是缺点，把不确定讲清楚才是专业。** 但要用 `suspected` 标出来，别混进 `confirmed`。

## 二、证据强度分级

按可复核程度排序，越靠前越硬：

| 级别 | 形态 | 例 |
|---|---|---|
| **A 可重跑** | 一条命令 + 确定输出 | `python x.py --at 0x120B3C98` 输出无 `rt_mq_send` |
| **B 可定位** | 具体地址 / 字节 / 偏移 / 返回码 | `0x120E32E8` 原指令 `10b5 4288` |
| **C 可观察** | 有明确感官判据的现象 | 手贴表盘有振动；录音在 200Hz 有峰 |
| **D 仅描述** | "实测有效"、"能跑通" | ← 不合格，等于没写 |

**至少要有 B。** 只有 D 的结论不许进 skill。

### 证据之间要独立

两条同源证据不算两条。典型错误：

```
❌ 证据1：改了 A 之后 B 变了
   证据2：B 变了说明 A 起作用了      ← 同一条信息的两种说法
```

```
✅ 证据1：改 0x120E32E8 为 b . 后，BLE 命令照收（行为无变化）
   证据2：该分发表只认 0x9xxx 段 ID（结构上就不是 BLE 帧的路由表）
```

## 三、坑的写法：必须有"误导性现象"

一个坑的价值 = **它骗了你多久** × **下次还会不会骗**。

```
❌ 不要用写死句柄的脚本推流。
```

```
✅ 写死句柄的推流脚本能"连上"，START 帧也发出去了，但永远收不到应答。
   现象看起来像"设备不响应"，实际是写到了普通模式的控制通道上——
   数据被丢弃，但 ACK 照回。
   判据：连上了、写成功了、零通知 → 先怀疑通道选错，别怀疑设备。
```

公式：

```
**现象**（看起来像什么）
**真因**（实际是什么）
**判据**（看到什么就该往哪个方向怀疑）
```

## 四、已推翻的结论：三件套

`refuted` 三条必填：`was` + `why_wrong` + `verify`。

```
**~~4 字节 XOR 密钥是 0xC6186C88~~**

- 当初被当成：整包解密的密钥
- 为什么错：起点常量就错了。把 HERMES_MAGIC 写成了样本自己的文件头
  （`00 07 D0 8B`），于是"header XOR 魔数"反推出的密钥必然也是假的。
- 怎么证伪的：整文件 XOR 后熵不降反升（6.79 → 7.21），且在 DEX 中零命中。
- 教训：**先验常量，再推理。** 常量级错误会级联出整串假结论。
```

**必须保留原文位置，不要删掉。** 删了就等于把"这条路走不通"的知识也删了。

## 五、正文排版

- **表格优先**：两三个对象的对比、参数表、错误码，一律用表格。散文写对比最难读。
- **命令用围栏代码块**，标注能直接复制。
- **地址一律写全 8 位十六进制**（`0x120B3C98`，不是 `120B3C98` 或 `0x120b3c98`）。
  大小写在一份文档内保持一致。
- **⚠️ 标记用于"会导致设备损坏/数据丢失"的警告**，普通坑用正文。
- 单篇超过 800 行就拆。按"对象"或"阶段"拆，不要按时间拆。
