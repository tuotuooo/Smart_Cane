# Skill 6：客户沟通与风险边界

> 人篇章（软技能线）Skill 6 · 底层操作系统见 [`human-social-engineering`](../human-social-engineering/)（Skill 0）。

## 一、定位

在**不激怒客户**的前提下划清支持边界、售后责任和操作范围。
免责声明会让客户觉得被推掉；风险告知会让客户觉得你专业。

## 二、触发场景

- 非原厂系统、授权版本不支持；
- 远程抓日志、客户提额外需求、故障复现；
- 需要说“不”但又不能把客户推走时。

## 三、核心动作

1. **风险告知代替免责声明**：说“支持边界在此，建议走 X 路径”，不说“我们不管”；
2. **不暴露内部能力上限**：删掉“只支持到某版本”这类内部限制；
3. **售后责任指向明确路径**：由渠道 / 原厂对接，不说“不在售后范围”；
4. **远程工具先讲目的和边界**：只收集日志、客户全程可见、可卸载；
5. **给三条路**：远程 / 自助采集 / 上门，不逼客户二选一；
6. **客户需求只记录不承诺**：资源、换机、扩容等，等 +1 定口径。

## 四、关键话术

> “这次想趁着故障还在把现场信息抓下来，远程只收集日志，您全程可见，用完可卸载。您看今天下午还是明天上午方便？”

（先讲目的和边界消除顾虑，再把时间选择权交给客户。）

## 五、红线

- 不说“公司流程要求”；
- 不承诺“马上修好”；
- 不反复劝客户装远程。

## 六、与 Skill 0 的关系

“免责框架 → 风险告知框架”正是 Skill 0 **框架控制**的直接应用：同一事实，换一种呈现就被感知成专业而非推责。话术发出前用 Skill 2 预审一遍。
